# Persistence review and fixes — 16 October 2026

Scope: persistence added between the archived 0.2.0 package and 0.3.0, followed by review of the fixes released in 0.3.1. The requirement is to save predictions across BB restarts and plugin reloads while reusing them only for an unchanged thread. Standards and behavior were reviewed independently.

## Standards

No documented BB storage, migration, input-validation, SDK-import, or lifecycle violations were found. No heuristic-only refactors were recommended. The candidate fixes were checked for alias cleanup, cancelled validation, disposal, and stale-generation protection.

## Behavior: three bugs fixed

1. **Temporary validation failures deleted valid saved predictions.** A provider/catalog/events request could fail before identifying the current context. The error state then deleted the disk entry, forcing another model call for an unchanged thread. Validation errors now leave the saved record intact without displaying its text. Retries can restore it. A failed validation also clears the unverified context key from the active state, so typing after an error is attached to the correct context when connectivity recovers.
2. **Delayed dismissals were ignored after restoration.** A cold request exposed a temporary generation ID, then restoration replaced it with the saved generation ID. A typing dismissal carrying the pending ID could arrive too late and be rejected, causing the suggestion to reappear. The coordinator now recognizes that pending ID as an alias for the restored prediction. The alias is removed when the generation changes, the entry is evicted, the thread is cleared, or the coordinator is disposed; it cannot dismiss a later context.
3. **Early typing attached dismissal to an obsolete saved context.** If a conversation changed while the plugin was offline, typing during validation inherited the old saved fingerprint. Returning to the now-empty composer could then generate again for the same current conversation. Typing now suppresses suggestions immediately while the read-only lookup finishes. The result records dismissal against the actual current fingerprint and never starts a prediction helper. If validation temporarily fails, suppression remains in place and a later retry can bind the dismissal correctly.

All three initial reproduction tests failed on 0.3.0 and passed after the fixes. A fourth test for typing after a failed warm validation also failed before its associated correction and passed afterward.
