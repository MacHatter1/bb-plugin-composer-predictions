# Bug review and fixes — 0.1.1

Reviewed the complete standalone plugin against its intended behavior: show a next-message prediction in an empty composer, accept only with Tab as an editable draft, and never submit it. The review was performed sequentially, with regression tests and a live BB check.

All findings below were fixed in version 0.1.1.

| Priority | Finding | Fix and verification |
| --- | --- | --- |
| P2 | A delayed dismissal could cancel a newer prediction for the same conversation because both shared the same context hash. Regeneration with identical wording could also remain hidden. | Each prediction attempt now has a unique generation ID used by both RPC dismissal and the ghost overlay. Tests cover stale dismissal and identical-text regeneration. |
| P2 | Typing before the initial RPC or context load completed could let a suggestion reappear after the user cleared their draft. | The server identifies an attempt immediately, retains dismissal even before context is available, and the frontend remembers edits until that attempt arrives. A public SDK composer test reproduces the delayed-response case. |
| P2 | An editor that remained connected after the composer shell moved or became ambiguous could retain its old overlay and Tab listener. Read-only and voice transitions could leave stale decorations visible. | The content script now releases decorations when the editor cannot be uniquely associated with its bridge and observes relevant mode attributes. It also respects a Tab already handled by the host. DOM tests cover these transitions. |
| P2 | Helpers surviving a server crash were never reconciled. An interaction committed before spawn returned could be missed by the membership-based event listener. | Startup reconciles only this plugin’s marked hidden workers; a new helper’s pending interactions are checked immediately after spawn. Failed cleanup remains tracked for disposal retry. SDK backend tests cover recovery ownership and the early-interaction race. |
| P3 | Unicode line separators could bypass the single-line prediction validator. | The parser rejects NEL, line separator, and paragraph separator in addition to ordinary line breaks. |

Execution options now travel with each immutable context snapshot rather than a mutable map keyed only by the source thread. This prevents cross-generation reuse of environment/provider options. The screen-reader announcement follows the same dismissal eligibility as the visible suggestion.

Validation: **24 tests passed**, TypeScript passed, the installed SDK pin matched BB, and both bundles built successfully. The tests now exercise the actual public composer handle and typed backend RPC through BB’s official SDK harnesses.

Live BB 0.46.1 check: typed and cleared a custom draft, verified server status stayed dismissed, explicitly regenerated, and pressed Tab to accept `Make it warmer.`. The source event log still contained exactly one user turn afterward, confirming no follow-up was sent. The plugin reported version 0.1.1, enabled/running, a compatible frontend bundle, and zero handler errors. The disposable test conversation was cleared, archived, and stopped after the check.

Remaining platform limits: BB has no native ghost-text slot, so placement depends on its composer DOM attributes. The SDK does not provide a global tool-disable policy for helper threads; they use no-tools instructions and cancel requested interactions, while core/other-plugin tools are not removed by a plugin-local empty tools list. These limits remain documented in [DESIGN.md](../DESIGN.md).
